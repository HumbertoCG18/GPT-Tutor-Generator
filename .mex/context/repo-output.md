# Repo Output Format

This documents the structure of the tutor repository generated by the tool. These
paths are generated output paths, not files expected to exist in this source repo.
Reviewed against the current generator modules on 2026-06-21.

## Critical Generated Files

```text
course/CRONOGRAMA_DETALHADO.md               # block-by-block render with linked code; only when timeline blocks exist
course/CRONOGRAMA_HEALTH.md                  # timeline/unit conflict and health report
course/CODE_HEALTH.md                        # auto-generated coverage report for code summaries + block linkage
course/code_curation.json                    # content-hash cache for Gemini summaries; safe to delete
course/references_curation.json              # content-hash cache for reference summaries and unit/topic mapping; safe to delete
course/COURSE_MAP.md                         # pedagogical map and primary tutor entry point
course/FILE_MAP.md                           # routing index with priority, unit, subtopic, and timeline hints
course/SYLLABUS.md                           # syllabus generated from SubjectProfile when available
course/GLOSSARY.md                           # glossary seeded and refined from course content
course/.timeline_index.json                  # internal timeline index used for regeneration
course/.block_identity.json                  # append-only stable block_uuid ledger for timeline rebuilds
course/.timeline_curation.json               # manual timeline curation keyed by stable block refs when available
course/.content_taxonomy.json                # internal unit/topic taxonomy used by routing
course/.assessment_context.json              # internal assessment scope/conflict context
course/.tag_catalog.json                     # internal tag vocabulary and manual-tag catalog
course/.card_block_map.json                  # internal Moodle card-to-timeline map, may include assignment due dates
course/.lessons_index.json                   # internal Moodle lesson date/topic index from course labels
course/SOURCE_REGISTRY.yaml                  # source registry for processed materials
student/STUDENT_STATE.md                     # student profile, current position, and progress state
student/STUDENT_PROFILE.md                   # student profile generated when available
student/PROGRESS_SCHEMA.md                   # progress schema for generated student state
student/batteries/                           # per-unit learning batteries and progress folders
exercises/EXERCISE_INDEX.md                  # exercise index, when exercise entries exist
exams/EXAM_INDEX.md                          # exam index, when exam entries exist
assignments/ASSIGNMENT_INDEX.md              # assignment index, when assignment entries exist
code/CODE_INDEX.md                           # code index, when code entries exist
whiteboard/WHITEBOARD_INDEX.md               # whiteboard index, when whiteboard entries exist
content/BIBLIOGRAPHY.md                      # bibliography index, when bibliography data exists
build/claude-knowledge/bundle.seed.json      # internal seed, not loaded eagerly by tutor projects
setup/INSTRUCOES_CLAUDE_PROJETO.md           # tutor instructions for Claude
setup/INSTRUCOES_GPT_PROJETO.md              # tutor instructions for GPT
setup/INSTRUCOES_GEMINI_PROJETO.md           # tutor instructions for Gemini
setup/CONTEXTO_TEMPORAL.md                   # compact schedule context for time-aware tutoring
system/TUTOR_POLICY.md                       # shared tutor policy
system/PEDAGOGY.md                           # shared pedagogical behavior
system/MODES.md                              # tutor mode definitions
system/OUTPUT_TEMPLATES.md                   # shared response templates
README.md                                    # generated repository readme
.gitignore                                   # generated repository ignore rules
```

## Source Modules That Generate These Files

| Source path | Responsibility |
|---|---|
| `src/builder/ops/pedagogical_regeneration.py` | Writes pedagogical, setup, system, student, and index artifacts during regeneration. |
| `src/builder/artifacts/repo.py` | Writes operational artifacts such as source registry, bundle seed, and build report. |
| `src/builder/artifacts/cronograma_health.py` | Renders CRONOGRAMA_HEALTH from timeline and curation conflict data. |
| `src/builder/artifacts/temporal_context.py` | Renders setup/CONTEXTO_TEMPORAL.md from current timeline blocks. |
| `src/builder/routing/file_map.py` | Builds routing indexes, unit matching, subtopic matching, and timeline scoring used by the generated routing index. |
| `src/builder/artifacts/deeptutor.py` | Exports selected generated artifacts into the DeepTutor knowledge directory. |
| `src/builder/core/code_summarization.py` | Generates Gemini summaries, assigns timeline blocks via concept overlap, prunes stale curation. |
| `src/builder/core/reference_summary.py` | Generates optional Gemini reference summaries and deterministic unit/topic mappings in references_curation.json. |
| `src/builder/core/reference_navigation.py` | Injects mapped references as support lines in COURSE_MAP with overflow pointers to BIBLIOGRAPHY. |
| `src/builder/runtime/gemini_client.py` | Lazy Gemini API client with exponential backoff on 429/5xx. |
| `src/builder/sources/moodle.py` | Backfills Moodle-derived entry/course signals and writes the generated lessons index and card-block map when source data is available. |
| `src/builder/sources/moodle_labels.py` | Parses Moodle card dates, lesson topic labels, and assignment due dates used by card/block routing. |
| `src/builder/timeline/card_block.py` | Loads and resolves card-to-block mappings consumed by routing. |
| `src/builder/timeline/block_identity.py` | Maintains stable timeline `block_uuid` ledger, migrates human truth refs, and guards missing ledgers. |
| `src/builder/timeline/curation.py` | Persists manual timeline curation in the generated course directory. |
| `src/builder/extraction/entry_signals.py` | Collects normalized entry signals, including `moodle_label`, for resolver and routing layers. |
| `src/builder/routing/concept_resolver.py` and `src/builder/routing/resolver_apply.py` | Optional, feature-flagged concept resolver that can overwrite block fields only when `use_concept_resolver` is enabled. |
| `src/builder/routing/anchor_placement.py` | Optional, feature-flagged temporal placement layer that writes additive temporal block fields. |
| `src/builder/core/stash_import.py` and `src/builder/core/stash_backfill.py` | Import and backfill source sections from subject stash/card folders. |

## How the Tutor Uses These Files

1. On first session, the tutor starts from the generated course map and routing index under the generated course directory.
2. It maps loaded materials to course units using the generated routing index as the navigation index.
3. It checks the generated student state before explanations so answers respect the student's current progress.
4. It uses the generated temporal context file when answers depend on the current schedule date.
5. It uses the generated bibliography file when COURSE_MAP reference support lines point to deeper reference context.
6. Internal generated course dotfiles and files under the generated build directory are operational metadata and should not be eagerly loaded as tutor knowledge.

## Generated File Map Format

The generated routing index is written during build. It contains:

- file paths for generated content entries
- priority weights
- unit and subtopic assignment hints
- timeline period hints where the course schedule supports them
- confidence markers for ambiguous matches
- computed block ids, confidence bands, and method/rationale fields when available
- stable block UUID references where timeline blocks have `block_uuid`
- optional `temporal_block_id` / `temporal_block_method` when anchor placement is enabled
- Moodle/source signals such as `source_section` and `moodle_label` when present in the manifest

The matching and routing logic lives in `src/builder/routing/file_map.py`.

## Multi-LLM Instruction Files

The build generates separate instruction files for each supported LLM from a
single run:

- Claude Projects instructions under the generated setup directory
- GPT instructions under the generated setup directory
- Gemini instructions under the generated setup directory

These are generated from the current course metadata, student profile, subject
profile, and repository feature flags in `src/builder/ops/pedagogical_regeneration.py`.

## What Does Not Exist in the Generated Repo

- LLM API calls at build time are confined to optional Gemini enrichment layers. Code summaries and reference prose summaries are skipped without a configured key; deterministic reference mapping can still run from fetched text.
- The concept resolver is not the default routing cutover; it is wired behind `use_concept_resolver` and only overwrites block fields when explicitly enabled.
- Anchor placement is not the default routing cutover; it is wired behind `use_anchor_placement` and writes additive temporal fields without replacing `computed_block_id`.
- No manual tutor-side rewrite of the generated course map or routing index; regeneration owns these files.
- `build/PROGRESS_SCHEMA.md` is legacy output cleaned from existing repos; current schema output is `student/PROGRESS_SCHEMA.md`.
